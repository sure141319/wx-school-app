# 小程序测试与发布检查

## 自动化门禁

在 `wxui_v2/` 目录执行：

```bash
npm run verify
```

该命令覆盖 TypeScript 类型检查、Node 行为回归测试和 CSS 生成物漂移检查。新增测试时优先验证可观察行为，例如请求参数、状态变化、缓存写入和用户提示；不要仅用正则断言源码的写法或文案排版。

## 轻量测试运行时的边界

`scripts/test-support/runtime.js` 会加载 TypeScript 模块，并用轻量 mock 执行页面或组件方法。它适合测试纯函数和方法级行为，但不等同于微信开发者工具或真机：

- 不渲染 WXML、WXSS；
- 不模拟组件 `observer`、完整生命周期和 Skyline 布局；
- 不保证 `wx.*` API、授权弹窗和系统剪贴板在真实环境中的表现。

涉及渲染、平台 API 或关键访客路径时，应保留少量发布前人工冒烟检查。

## 发布前人工冒烟

### 未登录访客查看并复制卖家 QQ

这是产品已确认的公开访问边界，每次准备发布小程序时检查：

1. 在微信开发者工具中清除缓存、本地存储和登录态，然后重新编译。
2. 以未登录状态打开一件已填写卖家 QQ 的在售商品详情。
3. 确认页面直接显示 QQ，且没有要求登录。
4. 点击复制联系方式，确认复制成功提示出现。
5. 将剪贴板内容粘贴到临时输入框，确认与页面显示的 QQ 完全一致。

建议在发布记录中写明检查日期、基础库版本、检查人和结果；失败时停止发布。
